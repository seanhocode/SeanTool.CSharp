# SeanTool.CSharp 設定檔與 CI 環境說明

## 你提到的第 4 點補充說明
你的第 4 點「不太懂意思」，在前一輪我指的是：
- 專案目前只有公開環境變數檔 public.env。
- 但 CI 實際還依賴 GitHub Secrets（例如 GITHUB_TOKEN 權限）。
- 這些 Secrets 的責任、用途、設定方式若沒有文檔，新維護者容易踩雷。

本文件已改成可直接執行的設定說明，不需要你先懂細節也能照表設定。

## 設定檔總覽

| 檔案 | 功能 | 目的 | 該如何設定 |
|---|---|---|---|
| Directory.Build.props | 全域 C# 編譯設定 | 統一所有專案的語言行為 | 一般保持 ImplicitUsings=enable、Nullable=enable；僅在全專案都同意時修改 |
| Directory.Build.targets | 建置時輸出診斷資訊 | 顯示 SDK/TFM 決策，利於排錯 | 正式環境可保留；若輸出太吵可降低 Message Importance |
| Directory.Packages.props | 集中管理 NuGet 版本 | 避免各專案版本漂移 | 新增套件時只改這裡的 PackageVersion，csproj 只寫 PackageReference Include |
| SharedFrameworks.props | 多目標框架策略 | 根據 SDK 版本決定 net8/net10 與 windows TFM | 若要固定只跑 net8，可把 net10 條件邏輯關閉 |
| Testing.props | 測試專案共用設定 | 將 *.Test 設為不可打包且是測試專案 | 若新增 UI demo 專案，不建議命名為 *.Test，或在此加入排除條件 |
| Packaging.props | 套件發布資訊 | 統一 Authors/Repository/GeneratePackageOnBuild | 發布策略變更時同步調整，避免個別 csproj 自行覆寫 |

## Workflow 與 env 檔說明

| 檔案 | 功能 | 目的 | 該如何設定 |
|---|---|---|---|
| .github/workflows/NugetPublish.yml | 偵測變更工具並打包發布 NuGet | 自動化發版 | 確認 INCLUDE_PROJECTS 與專案名稱一致；確認 GITHUB_TOKEN 有 packages 寫入權限 |
| .github/workflows/SyncRelease.yml | 收斂所有工具最新 nupkg 到 Release | 方便集中下載 | 確認 workflow_run 觸發條件、NuGet source 與 token 權限正確 |
| .github/workflows/public.env | 公開變數清單 | 管理要發布的工具名單與 NuGet Source | 維護 INCLUDE_PROJECTS 與 GITHUB_NUGET_SOURCE；新增工具時要同步更新 |
| Src/SingleFileSetting/Data/release.yml | SingleFileSetting 的示例資料檔 | 屬於工具示例資料 | 依你目前決策，先不納入重建流程 |

## public.env 變數說明

| 變數 | 用途 | 設定方式 |
|---|---|---|
| INCLUDE_PROJECTS | 指定 workflow 要處理的工具清單（分號分隔） | 新增/移除工具時同步修改，名稱需對應 csproj 名稱 |
| GITHUB_NUGET_SOURCE | GitHub Packages Source URL | 一般不常改，除非轉移組織或倉庫 |

## Secrets 與權限最小設定

| 項目 | 用途 | 建議設定 |
|---|---|---|
| GITHUB_TOKEN（Actions 內建） | dotnet nuget push、建立/更新 Release | Repo Settings > Actions > Workflow permissions 設為 Read and write |
| 若需跨 Repo 發布時的 PAT | 跨 repo 套件讀寫 | 只在必要時使用，範圍最小化（read:packages、write:packages） |

## 建議設定基準（重建期）
1. SharedFrameworks.props 先固定 net8.0 路線，避免重建期同時處理 net10 差異。
2. Testing.props 先把 UI demo 類專案與單元測試專案責任分離。
3. public.env 只保留真正要發布的工具，減少 CI 時間與失敗面。
4. 發版前用 workflow_dispatch 手動跑一次 NugetPublish，確認權限與來源設定都正確。

## 常見錯誤與排查
- 症狀：NuGet push 失敗。
- 優先檢查：GITHUB_TOKEN 權限、source 名稱是否一致、套件是否重複且未開 skip-duplicate。

- 症狀：測試專案被當成可打包專案。
- 優先檢查：Testing.props 條件是否命中 *.Test，專案命名是否符合規則。

- 症狀：突然多出 net10 編譯目標導致失敗。
- 優先檢查：SharedFrameworks.props 的 IsNet10Supported 判斷與本機 SDK 版本。
