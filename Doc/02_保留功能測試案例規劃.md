# SeanTool.CSharp 保留功能測試案例規劃

## 測試策略總覽
- 原則一：先保留核心功能可驗證性，再逐步重建完整測試。
- 原則二：UI 畫面先人工測試，但可純邏輯的部分要落地成自動化測試。
- 原則三：SqlTool 優先做到不依賴既有外部資料庫狀態。

## SqlTool 測試環境策略（依你的補充）

### 方案 A：不連線真資料庫
- 做法：把 SQL 產生邏輯、參數綁定邏輯抽成可獨立測試元件，對這層做單元測試。
- 優點：無外部依賴、速度快。
- 缺點：無法驗證實際 SQL Server 行為（交易、鎖定、BulkCopy、SP）。

### 方案 B：測試時從零建立資料庫，測完刪除（建議）
- 做法：每次測試 run 建立唯一 DB 名稱（例如 TestDb_GUID），套用 schema，測試結束 drop database。
- 優點：可驗證真實行為，又不依賴既有 DB 狀態。
- 缺點：需要本機可用 SQL Server 執行個體（LocalDB 或容器）。

### 推薦採用
- 採雙層測試：
- 單元測試：SQL 產生與映射邏輯（不連 DB）。
- 整合測試：自建自刪 DB 驗證交易與 I/O 行為。

## UI 人工測試項目清單

### FormControlTool（人工）
- SelectForm：選取後回傳值是否正確。
- TextForm：輸入內容是否完整回寫。
- ModelEditorForm：欄位編輯、存檔、再次載入是否一致。
- Grid：按鈕欄 callback 是否正確觸發、可編輯欄位是否生效。

### WPFTool（人工）
- ModelEditorWindow：模型載入、編輯、儲存流程是否正確。
- DynamicDataGrid：欄位定義與資料綁定是否對齊。
- Date/Time 輸入欄位：日期時間分離顯示與回寫是否一致。
